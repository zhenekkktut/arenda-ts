# Аренда ТС

Автономное приложение для учёта использования автомобиля, расчёта аренды, счетов, оплат, расходов и официальных документов.

## Возможности

- Во вкладке «Дни» — недельный календарь записей с суммой по ставке за единицу; быстрый ввод остаётся компактным.
- Расчёт по договору: постоянная часть с учётом простоя, показатель «количество × ставка» и большая из этих сумм.
- Учёт простоев с пропорциональным уменьшением постоянной части.
- История счетов, оплат и расходов с редактированием, фильтрами и категориями, которые можно добавлять, переименовывать и удалять.
- При создании счёта сумма распределяется по свободным деньгам дней до даты выставления. Последний день может быть включён частично; его остаток доступен следующему счёту. Количество бутылей в записях не делится и не меняется. Старые счета сохраняют суммы и оплаты; точная привязка подтверждается по порядку выставления.
- Два PDF: акт-расчёт и акт сверки. Топливо заказчика за месяц переводится в бутыли с округлением вверх; вычет сначала уменьшает переменную часть аренды. Если её не хватает, остаток уменьшает постоянную часть. В акте-расчёте показаны конечные значения без строки топлива. В сверке видны исходные дни и топливо, число вычтенных бутылей и разница округления.
- Версии документов можно удалить из архива с отменой удаления или загрузить их реквизиты и создать новую версию по текущим данным. Сохранённые PDF в «Загрузках» хранятся отдельно.
- Автоматические тексты для строки счёта, назначения платежа и письма.
- Условия договора и реквизиты автомобиля автоматически используются из сохранённых данных; в приложении их можно просмотреть.
- Выгрузка реестров и расчётов в Excel.

## Порядок работы

1. Если данные уже есть на другом телефоне или в прежней версии, восстановите JSON-копию в настройках: записи, счета и реквизиты подтянутся вместе с ней.
2. В календаре нажмите день: запишите бутыли, добавьте расход с этой датой или выберите «Без выезда — простой». Простой можно отметить за один день или диапазон полных дней. Он уменьшает постоянную часть пропорционально дням месяца. Пустая дата и запись с нулём автоматически простоем не становятся. Для топлива укажите, кто его оплатил.
3. По окончании месяца проверьте календарь, топливо и итог после вычета, затем закройте месяц через «Счета» → «Управление месяцем». Там же можно открыть месяц для исправлений, просмотреть список простоев и историю изменений.
4. Нажмите «Составить счёт»: номер, сумма остатка части аренды и точная привязка к свободным деньгам дней подставятся автоматически. Проверьте расшифровку и нажмите «Подтвердить и сохранить счёт». Сумму можно изменить для частичного счёта. При нехватке записей доступна отдельная кнопка уменьшения нового счёта до подтверждённой суммы. Приложение не меняет сумму ранее выставленного счёта само. Постоянную часть допустимо выставлять в течение месяца; переменная доступна после закрытия месяца и выставления постоянной.
5. Отмечайте фактически полученные оплаты, в том числе частичные. Оплаченный счёт сохраняйте в истории: он нужен для сверки и привязки дней.
6. Откройте «Счета» → «Акты за месяц» и подготовьте акт-расчёт и акт сверки. Номер обоих актов общий; данные берутся из записей, расходов, простоев, счетов и оплат. Проверьте даты и предпросмотр, сохраните PDF. В архиве можно открыть документ, удалить его версию или изменить реквизиты и создать заново.

На главной — выбор месяца, общая сумма «Осталось выставить», кнопка «Составить счёт» и компактная строка с переходом в календарь. Подсказка следующего действия появляется при необходимости; подробности доступны через «Показать расчёт». В настройках — JSON-копии, выгрузка Excel, оформление и быстрые кнопки расходов. Условия нашего договора используются из сохранённых данных. При чистом первом запуске без копии можно заполнить недостающие реквизиты; они подставятся в документы автоматически.

### Как сумма счёта связывается с днями

Например, 17 сентября развезено 145 бутылей (5 800 ₽), а 18 сентября — 255 (10 200 ₽). Счёт на 12 300 ₽ включает 5 800 ₽ за 17-е и 6 500 ₽ за 18-е. Оставшиеся 3 700 ₽ за 18-е подбираются для следующего счёта в пределах остатка аренды. В сверке 255 фактических бутылей за 18-е показаны один раз, рядом видны номера счетов и включённые суммы. Топливо вычитается общим итогом месяца и учитывается в лимите суммы к выставлению.

После восстановления прежней копии откройте «Составить счёт» → «Проверить счёт №…». Подтвердите предложенные даты старейшего счёта, затем следующего. Проверка не меняет полученные оплаты. Если записи исправлены и прежняя привязка больше не сходится, приложение попросит проверить счёт, сохраняя его сумму. Удаление или редактирование счёта освобождает только его распределение; другие счета не сдвигаются автоматически.

Если за завершённый месяц стоимость всех бутылей ниже постоянной части, разница отмечается как «Доплата до постоянной части», без вымышленных бутылей и дат. До завершения месяца такую доплату приложение не предлагает.

### Простой и плавность

«Без выезда — простой» означает полный календарный день, когда машина не ездила, включая выходные. При наличии положительного количества бутылей сначала проверьте запись: простой и развоз за тот же день одновременно не сохраняются. В календаре можно снять один день простоя из диапазона; оставшиеся дни сохранятся. Старые технические простои и их подтверждения остаются доступными для редактирования.

В настройках переключатель «Плавные переходы» отключает короткие анимации. Системное уменьшение движения тоже учитывается. Денежные суммы показываются сразу, без анимированного счётчика.

## Установить на Android

- Новая сборка появляется в [GitHub Actions](https://github.com/zhenekkktut/arenda-ts/actions/workflows/android-apk.yml): откройте последнюю успешную проверку и скачайте артефакт `arenda-ts-apk`.

На Android разрешите установку из браузера, откройте скачанный `arenda-ts.apk` и нажмите «Установить».

## Что хранится где

- Интерфейс целиком находится внутри APK и запускается без интернета, VPN и ChatGPT.
- Записи, счета, оплаты, расходы, простои и настройки документов хранятся только на телефоне.
- Excel-отчёт и полную резервную копию можно сохранить в выбранную папку.
- После удаления приложения локальные данные удалятся, поэтому резервную копию стоит делать регулярно.

## Сборка

Для текущей разработки используется ветка `feature/usn-tax-android` и PR №2. Workflow получает точный commit этой ветки; слияние PR выполняется отдельно.

Порядок сборки:

1. Установить зависимости через `npm ci` (Node.js 22).
2. Проверить расчёт, подбор периодов, архив и совместимость старых данных:
   `node --test --test-concurrency=1 tests/document-tools.test.mjs tests/fuel-deduction.test.mjs tests/invoice-periods.test.mjs tests/invoice-allocation.test.mjs tests/offline-allocation.test.mjs tests/workflow-tools.test.mjs tests/offline-archive.test.mjs tests/offline-documents.test.mjs tests/offline-undo.test.mjs tests/mobile-layout.test.mjs tests/tax-calculation.test.mjs tests/expense-shortcuts.test.mjs tests/offline-shortcuts.test.mjs`.
3. Собрать автономный интерфейс: `node node_modules/vite/bin/vite.js build --config offline/vite.config.ts`. Результат помещается в `android/app/src/main/assets`.
4. Собрать APK с Java 17 и Gradle 8.11.1: `gradle -p android :app:assembleDebug --no-daemon`.
5. В GitHub Actions проверить сохранение одностраничного и двухстраничного акта сверки и акта-расчёта на эмуляторе Android. PDF и изображения страниц входят в отчёт `android-pdf-test-report`.
6. После успешной проверки скачать `arenda-ts-apk`. Автономное приложение хранит записи на телефоне; перед переустановкой сохранить JSON-копию и затем восстановить её.

APK из PR имеет тестовую подпись: подпись может отличаться между сборками. Публикация постоянной ссылки в Releases выполняется workflow только после сборки ветки `main`.
