# Аренда ТС

Автономное приложение для учёта использования автомобиля, расчёта аренды, счетов, оплат, расходов и официальных документов.

## Возможности

- Во вкладке «Дни» — недельный календарь записей с суммой по ставке за единицу; быстрый ввод остаётся компактным.
- Расчёт по договору: постоянная часть с учётом простоя, показатель «количество × ставка» и большая из этих сумм.
- Учёт простоев с пропорциональным уменьшением постоянной части.
- История счетов, оплат и расходов с редактированием, фильтрами и категориями, которые можно добавлять, переименовывать и удалять.
- При создании счёта предлагаются периоды бутылей до даты выставления с учётом уже занятых дней. Даты можно изменить вручную; у старых счетов без периода требуется проверка привязки.
- Два PDF: акт-расчёт и акт сверки. Топливо заказчика за месяц переводится в бутыли с округлением вверх; вычет сначала уменьшает переменную часть аренды. Если её не хватает, остаток уменьшает постоянную часть. В акте-расчёте показаны конечные значения без строки топлива. В сверке видны исходные дни и топливо, число вычтенных бутылей и разница округления.
- Версии документов можно удалить из архива с отменой удаления или загрузить их реквизиты и создать новую версию по текущим данным. Сохранённые PDF в «Загрузках» хранятся отдельно.
- Автоматические тексты для строки счёта, назначения платежа и письма.
- Условия договора и реквизиты автомобиля автоматически используются из сохранённых данных; в приложении их можно просмотреть.
- Выгрузка реестров и расчётов в Excel.

## Порядок работы

1. Если данные уже есть на другом телефоне или в прежней версии, восстановите JSON-копию: записи, счета и реквизиты подтянутся вместе с ней.
2. Вносите бутыли по дням, расходы и подтверждённый простой. Если выезда не было, можно сохранить запись с нулём. Для топлива укажите, кто его оплатил.
3. По окончании месяца проверьте календарь, топливо и итог после вычета, затем закройте месяц.
4. Добавляйте фактически выставленные счета. Приложение предлагает следующий номер, свободный период по записям и оставшуюся сумму части аренды; предложения можно исправить. Постоянную часть допустимо выставлять в течение месяца, в том числе несколькими счетами. Переменная часть доступна после закрытия месяца и выставления постоянной.
5. Отмечайте фактически полученные оплаты, в том числе частичные. Оплаченный счёт сохраняйте в истории: он нужен для сверки и привязки дней.
6. Подготовьте акт-расчёт и акт сверки. Номер обоих актов общий; данные берутся из записей, расходов, простоев, счетов и оплат. Проверьте даты и предпросмотр, сохраните PDF. В архиве можно открыть документ, удалить его версию или изменить реквизиты и создать заново.

На главной подсвечен следующий шаг и показана кнопка нужного действия. Условия нашего договора доступны для просмотра и используются из сохранённых данных. В настройках меняются оформление и быстрые кнопки расходов. При чистом первом запуске без копии можно отдельно заполнить недостающие реквизиты сторон и автомобиля; они будут подставляться в документы автоматически.

## Установить на Android

- Новая сборка появляется в [GitHub Actions](https://github.com/zhenekkktut/arenda-ts/actions/workflows/android-apk.yml): откройте последнюю успешную проверку и скачайте артефакт `arenda-ts-apk`.

На Android разрешите установку из браузера, откройте скачанный `arenda-ts.apk` и нажмите «Установить».

## Что хранится где

- Интерфейс целиком находится внутри APK и запускается без интернета, VPN и ChatGPT.
- Записи, счета, оплаты, расходы, простои и настройки документов хранятся только на телефоне.
- Excel-отчёт и полную резервную копию можно сохранить в выбранную папку.
- После удаления приложения локальные данные удалятся, поэтому резервную копию стоит делать регулярно.

## Сборка

Для текущей разработки используется ветка `feature/usn-tax-android` и PR №2. Workflow получает точный commit этой ветки; слияние PR выполняется отдельно.

Порядок сборки:

1. Установить зависимости через `npm ci` (Node.js 22).
2. Проверить расчёт, подбор периодов, архив и совместимость старых данных:
   `node --test --test-concurrency=1 tests/document-tools.test.mjs tests/fuel-deduction.test.mjs tests/invoice-periods.test.mjs tests/workflow-tools.test.mjs tests/offline-archive.test.mjs tests/offline-documents.test.mjs tests/offline-undo.test.mjs tests/mobile-layout.test.mjs tests/tax-calculation.test.mjs tests/expense-shortcuts.test.mjs tests/offline-shortcuts.test.mjs`.
3. Собрать автономный интерфейс: `node node_modules/vite/bin/vite.js build --config offline/vite.config.ts`. Результат помещается в `android/app/src/main/assets`.
4. Собрать APK с Java 17 и Gradle 8.11.1: `gradle -p android :app:assembleDebug --no-daemon`.
5. В GitHub Actions проверить сохранение одностраничного и двухстраничного акта сверки и акта-расчёта на эмуляторе Android. PDF и изображения страниц входят в отчёт `android-pdf-test-report`.
6. После успешной проверки скачать `arenda-ts-apk`. Автономное приложение хранит записи на телефоне; перед переустановкой сохранить JSON-копию и затем восстановить её.

APK из PR имеет тестовую подпись: подпись может отличаться между сборками. Публикация постоянной ссылки в Releases выполняется workflow только после сборки ветки `main`.
